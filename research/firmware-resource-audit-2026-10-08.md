# Emviary E1002 firmware audit and release evidence

Audit started October 8, 2026 and continued October 9. Baseline was the physical E1002 running v0.6.2, not an assumed checkout. The target is an ESP32-S3 reTerminal E1002 with an 800 x 480 Spectra6 panel. The backend retains all artwork, dithering, selection, history and schedule logic. Private backups preserve the installed application, NVS, OTA metadata, configuration, symbols and serial logs. No secrets or backups are published.

## Decision and acceptance boundary

The audit produced a materially smaller application, stricter content validation, serialized image/update/sleep ownership, safer persistence and focused recovery pages. Physical testing exposed defects beyond the original host suite, including an unsupported SDK SPI wait, two pending navigations behind an HTTP refresh, duplicate panel sleep and an OTA main-task stack overflow. Each was addressed with a focused change and additional evidence. This remains a prerelease acceptance exercise, not a claim of production certification.

There is no current-measurement equipment. Binary bytes, stack reservations, heap and duration are not energy measurements. Three months between charges and complete resolution of the historical white-screen symptom remain unverified. The most persuasive remaining test is an unattended battery-powered overnight and multi-day retention run with serial/reset evidence and photographs.

## Prioritized findings and implementation

| Priority | Evidence and defect | Smallest implemented change | Verification and residual risk |
| --- | --- | --- | --- |
| P1 | Incomplete/trailing gzip, bad CRC, wrong pixel count and incompatible inks could reach paint. | Require exact packed output, stream end/full input, CRC and valid six-color nibbles before any panel write. | Actual reader host faults; physical corrupt, truncated and invalid-ink bodies rejected before panel traffic. |
| P1 | Transfer paths shared temporary files; current source was replaced before decoding. | Recursive whole-operation mutex; pending files promoted only after checked refresh; complete bounded reads/writes/close. | Actual lifecycle/write faults and device HTTP/button concurrency. Promotion across multiple files is not a globally atomic transaction. |
| P1 | Driver reported success after BUSY timeout and ignored SPI failure. | Return checked controller/SPI status; abort without success metadata. | Actual driver fault harness and successful physical refresh. SPI acquisition/polling require SDK portMAX_DELAY, so no hard whole-wake deadline is claimed. |
| P1 | Sleep raced refresh, OTA, periodic work or queued navigation. | Image/periodic/navigation barriers protect teardown. Acquire image ownership before claiming the single last-press queue. | Actual threaded navigation tests and device sleep/refresh observations. Permanently stalled CPU/driver work still needs watchdog or USB recovery. |
| P1 | Automatic LittleFS formatting and NVS/Wi-Fi erasure threatened saved data. | Preserve bytes and profiles on errors; retry or expose green-button recovery instead. | Actual mount fault tests and saved-profile fallback on hardware. Corrupt physical NVS and interrupted persistence remain untested. |
| P1 | Loose/truncated provisioning and configuration input, secret echo and authenticated redirects. | Complete bounded bodies, strict field lengths/escapes/JSON depth/NUL checks; write-only secrets; refuse bearer redirects. | Seven real malformed-input rejections with unchanged config; host boundary tests. Optional local HTTP auth is disabled in the retained configuration. |
| P1 | OTA metadata/install raced and trusted insufficient bounds. | Serialized immutable candidate, complete bounded metadata, inactive-slot/size/full SHA256/project/version validation. | Target builds, host boundaries and physical installation below. Existing bootloader does not provide automatic post-boot rollback. |
| P1 | v0.7.1 automatic installation overflowed the 6144-byte main stack, repeatedly rebooting. | Temporary 12288-byte wake OTA worker; persisted source/digest checkpoint holds identical automatic retry after install panic/watchdog. | Real panic captured; cloud offer paused to recover; four policy tests and physical corrected OTA below. Retry guard is not boot rollback and power loss alone does not create a crash hold. |
| P2 | Panel shutdown after successful refresh repeated POF on an already sleeping controller, waiting 40 seconds. | Track confirmed sleep only in the same boot; skip duplicate protocol, retain pads/rail shutdown. | Real-driver sleep tests; physical corrected trace below. Unknown/304-only boot paths remain conservative and may still wait 40 seconds. |
| P2 | Scheduled battery wakes reserved an idle 16 KiB rotation task and duplicate 8 KiB green task. | 4 KiB power supervisor, lazy rotation worker, common continuously debounced button scanner. | Source accounting; no energy claim. A temporary 12 KiB OTA worker now exists during wake checks. |
| P2 | Timer callback performed blocking RTC/SNTP work in shared ESP timer task. | Callback only notifies a 4 KiB periodic worker; mutex/barrier protects execution and sleep. | Actual periodic-source notification, duplicate, creation-failure and sleep tests. |
| P2 | Upstream gallery, EXIF and processing assets did not serve backend-rendered frame use. | Compact setup/recovery pages and narrower E1002 HTTP routes; omit local processing/calibration initialization and image headers. | Target link size and local page/config checks. Retained decoders/splash/recovery dependencies are not removed merely because their source looks unused. |

Source attribution and upstream board support remain. The E1002 already skipped HA work, SD mounting and the SD rail; deleting inert references alone would not prove runtime savings. No clock, RTOS tick, rail sequencing, bootloader, partition or irreversible security settings were changed.

Task stack arguments excluding TCB/semaphore/allocator overhead: old scheduled power task 16384 bytes becomes 4096 supervisor + 4096 periodic; the separate green task saves another 8192 bytes. Interactive battery source reservations fall by 20480 bytes; USB reservations fall by 4096 bytes. The new wake OTA worker transiently adds 12288 bytes for metadata checking/install, so these reductions must not be presented as a universal simultaneous-RAM saving. It deletes itself after a no-update/error check; active rotation remains allocated after a USB transition until sleep/reset.

Diagnostics retain an 8192-byte ring and 4096-byte writer task, with sync after 32 lines or five seconds. RTC retains image metrics rather than committing each refresh. Daily successful SNTP timestamps and offered OTA checkpoints still write NVS. Actual fsync/write totals and CPU task utilization were not instrumented. SDK remains 160 MHz maximum, debug optimization and 1000 Hz tick; speculative frequency changes were avoided.

## Automated and physical validation

197 of 197 host tests pass. Harnesses execute the real reader, GCA driver, storage, periodic and shared navigation sources with RTOS/ESP mocks. They cover CRC/truncation/output/ink faults, write and driver failure, storage preservation, callback/task cleanup, barriers, debounce/coalescing, HTTP/OTA contention, JSON/URL/config bounds, cron/DST and OTA crash-hold policy. They do not reproduce radio, scheduler, brownout, real flash corruption or all HTTPS OTA failures.

Physical E1002 observations:

- Both local hostnames return the installed version; compact recovery page loads. Seven malformed configuration inputs returned 400 and left URL/name unchanged. GET secrets are presence flags only.
- v0.7.0 application-only USB installation retained the visible picture, confirmed by user. Sleep testing then caught unsupported finite SPI acquisition. Its notes warn against installation; immutable binaries were not overwritten. v0.7.1 restored the SDK contract and made the host mock faithful.
- GitHub HTTPS fixtures with cloud/custom credentials cleared rejected corrupt CRC in 1.56 s, truncated body in 1.47 s, invalid ink in 1.68 s and oversized body in 22.06 s (three attempts). Credentials/original URL were restored privately afterward. A valid 22116-byte three-bird image completed real GCA refresh in 28.70 s; 304 repeat completed in 1.69 s without panel update.
- Authenticated cloud valid fixture completed refresh in 31.43 s, 304 in 4.50 s and corrupt CRC rejected in 4.24 s before painting. Direct fixture copies avoided rendering; an automatic fixture preparation after midnight created a second isolated image. The fixture and its owned files are removed after testing.
- Temporary unavailable-first Wi-Fi profile plus original second profile and near-term cron armed 67 s sleep. Timer wake selected profile 2/2, acquired IP in 4720 ms, handled a failed cloud request, held off 300 s and slept. USB powered; original profile list and Denver `15 3 *` were restored/read back. This validates timer/profile mechanics, not an unattended nightly battery cycle.
- Serial on v0.7.1 showed two pending requests behind HTTP panel work and a duplicate 40 s panel-sleep BUSY wait. Both caused focused real-source regressions and v0.7.2 fixes.
- v0.7.2 was published but not installed. Its offer exposed the old v0.7.1 main-stack overflow before download and selected-slot change. Pausing cloud updates recovered the existing firmware. The fixed source is released separately below.

### Final release and acceptance evidence

Source `fb3e95234dd9479d2899a67ba41df4018145de18` produced immutable v0.7.3 and v0.7.4 prereleases with unchanged partition binaries, each 1560272 application bytes. The old dedicated manual OTA worker installed v0.7.3 into slot 0 successfully. A controlled reset then ran the new wake worker, downloaded/validated v0.7.4 into slot 1 and booted it without panic. The install worker reported 5328 bytes minimum free stack; no-update wake checks reported 7024 to 7032 bytes. Saved schedule/profile/config survived both updates. Those are real OTA observations, not CI-only evidence.

Final v0.7.5 additionally persists the crash checkpoint before entering the non-inline installer, so installer-frame entry is inside the guard. Crashes during metadata/allocation or before checkpoint commit remain outside it; a stale marker after power loss/failed clearing may conservatively hold a later retry. On v0.7.4 a repaired isolated valid cloud fixture completed in 31.62 s. Sleep then logged confirmed same-boot panel sleep and skipped duplicate commands. Panel sleep entry at 254473 ms and system deep sleep at 254492 ms were 19 ms apart, without the old 40 s wait. This is a duration observation on USB, not an energy result. The delayed-sleep task reported 1816 bytes minimum free stack. The earlier fixture 503 test was an audit-fixture hash mistake after the date changed, not a firmware decoder failure; it retained the current picture.

No white-button presses were captured during the corrected v0.7.4 refresh, and the physical picture/button confirmation is pending. Actual-source coalescing regressions pass, but that is not a physical button acceptance result. Final immutable candidate: [v0.7.5 prerelease](https://github.com/lstepnio/Emviary-firmware/releases/tag/v0.7.5), source `67e973afafa93a60c404d1b625a265ef041cdfd1`, [ESP-IDF v6.0 E1002 build](https://github.com/lstepnio/Emviary-firmware/actions/runs/37892541223). Application is 1560352 bytes, 443952 fewer than baseline (22.2 percent). SHA256 `dea864b1771f6d70011828379730a25da5919d540d41c5a016739f1e0f19dc9f`. Downloaded binary, SHA256SUMS, manifest, source SHA and CI artifact match. Partition binary is identical to baseline. ELF text/data/BSS: 1128053 / 444990 / 2676735 bytes. Target disassembly confirms preparation precedes non-inline installer entry on both paths. The physical E1002 subsequently downloaded/validated v0.7.5 on wake from v0.7.4, wrote inactive slot 0 and booted v0.7.5. The source worker doing that installation reported 5272 bytes minimum free stack. Final no-update check and HTTP diagnostics are separate samples; the final prepare-helper ordering was verified in compiled code, not by deliberately inducing a hardware panic.

Final clean-running sample: internal free/minimum 149959 / 114439 bytes, largest 49152; PSRAM free/minimum 8191168 / 8123380; HTTP minimum stack headroom 10084. Seven malformed-input rejection checks passed again on v0.7.5. These clean samples do not include a matched peak-TLS failure stress run. A final refresh from the normal authenticated service completed in 31.30 s, including 3885 ms download of 16152 bytes, with checked GCA completion. Afterward internal free/minimum was 149707 / 92075, largest 49152; PSRAM minimum 7975092; HTTP minimum headroom 6260. These are observed samples, not matched energy or peak-memory improvements. Final no-update worker minimum free stack was 7088 bytes. Sleep again skipped duplicate panel commands, with panel entry at 152849 ms and device deep sleep at 152868 ms, a 19 ms interval; delayed-sleep task headroom was 1820 bytes. The frame was left asleep with the freshly delivered picture; visual confirmation is pending.

The original image URL/credentials, saved network and Denver `15 3 *` rule are retained. Cloud update policy is restored to automatic with no pin; authenticated current-version discovery offers no update. Temporary cloud fixture and public GitHub fixture branch were cleaned up.

## Recovery and remaining work

Routine recovery is application-only. Stop serial monitors; privately save NVS/OTA metadata; identify the selected slot before writing. Slot 0 is `0x20000`, slot 1 `0x3a0000`, each `0x380000` bytes. Use the exact E1002 application with verified release digest, write only the selected application and verify flash hash/version/saved config/panel. Never erase-all or routinely flash a merged image. Bootloader/partitions remain unchanged. A historical active offset must not be assumed after OTA. Known-good baseline and later accepted artifacts are retained privately.

Ordinary inactive-slot validation/download failure leaves the selected slot unchanged. Existing bootloader rollback is disabled. A correctly hashed defective new application can still require USB recovery. A separately approved bootloader migration with offline self-test would be the stronger recovery design; this audit does not implement that migration.

Optional local Basic Auth is disabled in the observed configuration, is unencrypted over HTTP, and legacy auth-load failure remains fail-open. Configuration is not globally transactional. Core-dump boot logs reported missing/corrupt handling despite a core-dump partition; diagnostic capture is incomplete. Public mirror tracks delivered bytes, not a confirmed physical-panel acknowledgment. These are remaining risks, not verified fixes.

Recommended acceptance follow-up: battery-input profiler and usable-capacity measurement; at least ten matched normal/304/failed/manual cycles; unattended 03:15 Denver overnight plus multi-day picture retention; physical offline green provisioning, USB attach/detach, interrupted OTA/persistence, brownout and corrupt-NVS recovery. Capture reset/wake causes, photographs, phase timings, heap/min/largest blocks, every-task stack minima and actual storage/network totals. Manual interactions and board/self-discharge overhead must be included in battery forecasts.
